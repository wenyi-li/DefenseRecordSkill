# 最终答辩记录

生成最终 Markdown 答辩记录。除非用户提供了官方模板，否则使用 `templates/defense_minutes_template.md`。

## 要求

- 按答辩人组织内容。
- 多答辩人或长录音场景下，最终记录必须由“逐答辩人抽取结果”汇总生成；不要直接从整场全文压缩成最终记录。
- 汇总前确认已生成 `qa_chunk.md`，其中按答辩人保存了问答片段原文，格式与 `transcript_output/transcript.md` 一致。
- 将陈述概述与评委问答分开。
- 保留问答格式：
  - `问：`
  - `答：`
- 最终 `评委问答` 和 `评委建议` 中不要保留逐条 `时间范围：...`；时间范围只写在每位答辩人章节开头的基本信息处。
- `答：` 后必须直接写回答内容，不要添加 `答辩人说明`、`答辩人表示`、`答辩人解释说`、`答辩人认为`、`答辩人确认`、`答辩人未能`、`答辩人举了`、`该同学表示` 等转述主语或引导语。
- `回应：` 后必须直接写实际回应或承诺；能写 `会修改`、`接受`、`已记录` 时，不要写 `答辩人表示会修改`。
- 将仅建议类交流单独保留为 `建议：` 和 `回应：`；不要强行改写成问答。
- 不要增加任何回答质量评价字段，也不要评价答辩人回答是否充分、是否正面或是否完整。
- 使用简洁、客观、适合秘书审核的语言。
- 不要生成官方答辩决议。
- 包含术语修正和低置信度说明。
- 不要隐藏不确定性。
- 生成前检查全文，若存在 `答：答辩人`、`回应：答辩人`，或 `评委问答` / `评委建议` 中存在逐条 `时间范围：`，必须改为符合要求的格式后再输出。

## 生成前覆盖检查

对每位答辩人逐项检查：

- 问答记录的最早时间应覆盖该答辩人 `qa` 片段中第一个实质评委问题或建议，不得从中段开始。
- 问答记录的最晚时间应覆盖该答辩人 `qa` 片段中最后一个实质评委问题、建议或确认性回应，除非该内容属于下一位答辩人的过渡。
- 源片段中每个独立评委发起点都应在最终记录中对应一条 `问：` 或 `建议：`。
- 如果为了简洁合并了连续追问，合并后的问题必须保留所有核心问题点。
- 不要用“每位答辩人固定 3 条问答”之类的篇幅模式压缩记录；问答条数由源片段决定。
- 覆盖检查发现缺失时，先补齐对应问答或建议，再生成最终 Markdown。

## 输出文件

优先写入：

```text
defense_records.md
```

如果不适合写入文件，则直接在对话中提供 Markdown。
